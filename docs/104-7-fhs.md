# 3.16 Jerarquía de directorios y localización de ficheros

En Windows cada disco tiene su letra (`C:`, `D:`...). En Linux hay **un único árbol** que empieza en la raíz `/`, y todo (discos, particiones, USB, recursos de red) se "cuelga" de algún punto de ese árbol.

Para que todas las distribuciones organicen ese árbol de forma parecida existe el **FHS** (*Filesystem Hierarchy Standard*), que dice qué debe ir en cada directorio. Conocerlo es imprescindible para saber dónde buscar un fichero de configuración, un log o un programa.

## Los directorios principales

| Directorio | Contenido |
|---|---|
| `/` | Raíz de todo el sistema de archivos |
| `/bin` | Comandos básicos para todos los usuarios (`ls`, `cp`, `cat`...) |
| `/sbin` | Comandos básicos de administración (`fdisk`, `ip`, `reboot`...) |
| `/boot` | Lo necesario para arrancar: el kernel (`vmlinuz`), el *initramfs* y GRUB |
| `/dev` | Ficheros de dispositivo (`/dev/sda`, `/dev/null`, `/dev/tty1`...) |
| `/etc` | **Configuración** del sistema y de los servicios (solo texto, sin programas) |
| `/home` | Directorios personales de los usuarios |
| `/root` | Directorio personal de `root` |
| `/lib`, `/lib64` | Bibliotecas compartidas que necesitan `/bin` y `/sbin`, y módulos del kernel |
| `/media` | Puntos de montaje automáticos de medios extraíbles (USB, DVD) |
| `/mnt` | Puntos de montaje temporales que monta el administrador a mano |
| `/opt` | Software adicional que se instala en un paquete propio (por ejemplo, programas comerciales) |
| `/proc` | Sistema de archivos **virtual** con información de procesos y del kernel |
| `/sys` | Sistema de archivos **virtual** con información de dispositivos y controladores |
| `/run` | Datos de ejecución desde el arranque (PID, sockets); se vacía al reiniciar |
| `/srv` | Datos de los servicios que ofrece la máquina (web, FTP...) |
| `/tmp` | Ficheros temporales; puede vaciarse al reiniciar |
| `/usr` | Programas, bibliotecas y documentación de uso general (la mayor parte del software) |
| `/var` | Datos **variables**: logs, colas de correo e impresión, cachés, bases de datos |

!!! info "`/usr` unificado"
    En las distribuciones actuales (Debian 12, Ubuntu, Fedora, Rocky...), `/bin`, `/sbin` y `/lib` son **enlaces simbólicos** a `/usr/bin`, `/usr/sbin` y `/usr/lib`. Compruébalo con `ls -l /`. El FHS sigue describiéndolos por separado, y así aparecen en el examen.

### Dentro de `/usr`

| Directorio | Contenido |
|---|---|
| `/usr/bin` | La mayoría de los programas de usuario |
| `/usr/sbin` | Programas de administración no esenciales |
| `/usr/lib` | Bibliotecas |
| `/usr/share` | Datos independientes de la arquitectura: documentación, manuales, iconos |
| `/usr/local` | Software instalado **a mano** por el administrador (compilado, por ejemplo), con su propio `bin`, `lib`, etc. |
| `/usr/include` | Cabeceras para compilar en C |

### Dentro de `/var`

| Directorio | Contenido |
|---|---|
| `/var/log` | **Registros** (logs) del sistema y de los servicios |
| `/var/cache` | Cachés de las aplicaciones (por ejemplo, los paquetes descargados por `apt`) |
| `/var/lib` | Datos de estado de las aplicaciones (bases de datos de paquetes, de MySQL...) |
| `/var/spool` | Colas: impresión, correo, tareas de `cron` |
| `/var/tmp` | Temporales que **sobreviven** a un reinicio |
| `/var/www` | Sitios web (en Debian y Ubuntu) |

### Directorios ocultos en el `home`

Los programas guardan la configuración de cada usuario en su directorio personal, en ficheros y carpetas ocultos (empiezan por `.`): `~/.bashrc`, `~/.ssh/`, `~/.config/`, `~/.local/share/`, `~/.cache/`...

## Directorios "estáticos" y "variables"

El FHS clasifica los datos según dos criterios, y eso ayuda a decidir cómo particionar el disco y qué copiar en las copias de seguridad:

| | Compartibles entre máquinas | No compartibles |
|---|---|---|
| **Estáticos** (no cambian solos) | `/usr`, `/opt` | `/etc`, `/boot` |
| **Variables** | `/var/mail`, `/var/spool/news` | `/var/run`, `/var/lock` |

## Localizar ficheros

### `find`

Ya lo vimos en el apartado 3.4: recorre el árbol en tiempo real, así que siempre es exacto pero puede ser lento.

### `locate` y `updatedb`

`locate` busca en una **base de datos** con los nombres de todos los ficheros del sistema, por lo que es casi instantáneo. A cambio, solo encuentra lo que había la última vez que se actualizó esa base de datos.

```bash
$ sudo apt install plocate       # en Debian/Ubuntu (o mlocate en sistemas antiguos)
$ locate sshd_config
$ locate -i readme               # sin distinguir mayúsculas
$ locate -c '*.conf'             # cuenta los resultados
$ locate -e informe              # solo los que todavía existen
$ sudo updatedb                  # actualiza la base de datos
```

La base de datos se actualiza sola una vez al día (con una tarea programada). Si acabas de crear un fichero, `locate` no lo encontrará hasta que ejecutes `updatedb`.

Qué se incluye o no se configura en `/etc/updatedb.conf` (por ejemplo, con `PRUNEPATHS` se excluyen directorios como `/tmp` o los montajes de red).

### `which`, `type` y `whereis`

Sirven para localizar **comandos**:

```bash
$ which ls                       # qué fichero se ejecuta (buscando en el PATH)
/usr/bin/ls
$ which -a python3               # todos los que hay en el PATH
$ type ls                        # qué es para Bash: alias, función, interno o fichero
ls is aliased to `ls --color=auto'
$ type cd
cd is a shell builtin
$ whereis ls                     # binario, código fuente y página de manual
ls: /usr/bin/ls /usr/share/man/man1/ls.1.gz
$ whereis -m passwd              # solo las páginas de manual
```

### Resumen de herramientas de búsqueda

| Herramienta | Busca en | Velocidad | ¿Siempre actualizado? |
|---|---|---|---|
| `find` | El árbol real, en el momento | Lenta en árboles grandes | Sí |
| `locate` | Una base de datos | Muy rápida | No: depende de `updatedb` |
| `which` | Los directorios del `PATH` | Inmediata | Sí |
| `whereis` | Rutas típicas de binarios, fuentes y manuales | Inmediata | Sí |
| `type` | Alias, funciones, internos de Bash y `PATH` | Inmediata | Sí |

## Ejercicios

**1.** Ejecuta `ls -l /`. ¿Qué directorios de la raíz son enlaces simbólicos? ¿A dónde apuntan?

??? success "Solución"
    ```bash
    $ ls -l / | grep '^l'
    ```
    En distribuciones modernas aparecen `bin`, `sbin`, `lib` (y `lib64`) apuntando a sus equivalentes en `/usr`.

**2.** ¿En qué directorio buscarías cada una de estas cosas?

- a) La configuración del servidor SSH.
- b) El log de autenticación.
- c) El kernel que arranca la máquina.
- d) Un programa que has compilado tú mismo.
- e) La información de la CPU.
- f) El disco duro como dispositivo.
- g) Las páginas de manual.

??? success "Solución"
    a) `/etc/ssh/` · b) `/var/log/` (`auth.log` o `secure`) · c) `/boot/` · d) `/usr/local/bin/` · e) `/proc/cpuinfo` · f) `/dev/` (`sda`, `nvme0n1`...) · g) `/usr/share/man/`

**3.** Mira el tamaño de los principales directorios del sistema con `du`. ¿Cuál ocupa más? ¿Por qué `/proc` dice que ocupa 0?

??? success "Solución"
    ```bash
    $ sudo du -sh /* 2>/dev/null | sort -h
    ```
    Normalmente `/usr` es el más grande (los programas). `/proc` y `/sys` son sistemas de archivos virtuales: el kernel genera su contenido en memoria al consultarlo, no ocupan disco.

**4.** Usa ficheros de `/proc` para averiguar: la versión del kernel, la memoria total y cuánto tiempo lleva encendida la máquina.

??? success "Solución"
    ```bash
    $ cat /proc/version
    $ grep MemTotal /proc/meminfo
    $ cat /proc/uptime        # segundos encendido y segundos de inactividad
    ```

**5.** Instala `plocate` (o `mlocate`), actualiza la base de datos y busca todos los ficheros llamados `passwd`. ¿Cuántos hay?

??? success "Solución"
    ```bash
    $ sudo apt install plocate
    $ sudo updatedb
    $ locate -b '\passwd'
    $ locate -b -c '\passwd'
    ```
    `-b` busca solo en el nombre (no en la ruta) y la barra delante obliga a que el nombre sea exactamente `passwd`.

**6.** Crea un fichero `secreto_iso.txt` en tu home y búscalo con `locate`. ¿Lo encuentra? ¿Qué tienes que hacer? Después bórralo y vuelve a buscar. ¿Qué pasa?

??? success "Solución"
    No lo encuentra hasta ejecutar `sudo updatedb`. Al borrarlo, `locate` lo sigue mostrando hasta la siguiente actualización; con `locate -e` solo se muestran los que aún existen.

**7.** ¿Dónde está el ejecutable de `tar`? ¿Y su página de manual? ¿`echo` es un programa o un comando interno de Bash?

??? success "Solución"
    ```bash
    $ which tar
    $ whereis tar
    $ type echo        # echo is a shell builtin
    $ which -a echo    # además existe /usr/bin/echo
    ```
    `echo` existe de las dos formas; Bash usa su versión interna.

**8.** Compara el tiempo que tardan `find / -name "*.conf"` y `locate "*.conf"` (antepón `time`). ¿Devuelven el mismo número de resultados?

??? success "Solución"
    ```bash
    $ time sudo find / -name "*.conf" 2>/dev/null | wc -l
    $ time locate "*.conf" | wc -l
    ```
    `locate` es muchísimo más rápido. El número puede variar: `locate` no incluye los ficheros creados desde el último `updatedb` ni las rutas excluidas en `/etc/updatedb.conf`, y `find` sí ve el estado actual.

**9.** Explica la diferencia entre `/tmp` y `/var/tmp`, y entre `/media` y `/mnt`.

??? success "Solución"
    `/tmp` es para temporales que pueden desaparecer al reiniciar (a menudo está en memoria); `/var/tmp` es para temporales que deben sobrevivir a un reinicio. `/media` es donde el sistema monta automáticamente los dispositivos extraíbles; `/mnt` es para montajes temporales que hace el administrador a mano.
